## Binding and ownership contract

`common_transaction_profile::Profile::new` remains the offline requested plan.
Its settings, full catalog, E0, C0/D0 and H0 retain their existing bytes. A requested
raw carrier policy is a separate explicit service input; no proof is fabricated
for inspection. After real TLS/member authentication, `bind_outer(&self,
AuthenticatedOuter)` returns an effective profile retaining the original plan
and the genuine opaque proof. Rebinding an already bound profile is refused.

The effective envelope and setup digest are derived by the runtime's paired-role
carrier contract from E0/H0, both complete role resource templates, the complete
catalog and actual outer proof. Both roles use the same canonical resource order.
The actual role-local template is selected only after that commitment. The DAG is
E0/H0 plus real outer proof to E1, then complete C1/D1 and effective setup H1;
there is no hash fixed point. Public Info or copied status fields cannot construct
the opaque proof or authenticated Parts.

The sole additional DataV1 opcode is checked and charged in the gate overhead,
shared control wire overhead and every selected stream delivery overhead. All
payload, source, message, count, MTU and native limits remain unchanged. A plan
that cannot fit the real carrier is refused, not rounded or reduced. Both role
templates and the whole catalog are checked before the effective profile is
released. Actual endpoints, outer member, address family and attachment layer
must match the retained requested plan.

The effective catalog also adds exactly that byte to the represented carrier
overhead in both Aligned/Packed recovery directions and both Rolling geometry
directions. Swift descriptor fields are unchanged. Each complete descriptor and
the complete catalog are rebuilt with the maintained checked constructors; all
other fields, initial-member selection and supported members are preserved.
`requested_catalog()` retains the exact E0 descriptors/root, while `catalog()`
reports the complete effective E1 catalog. Tight geometries are refused instead
of shrinking record bodies or silently enlarging bursts.

`settings()` remains the requested E0 settings. `requested_configuration()` and
`requested_envelope()` expose H0/E0; `carrier_binding()` exposes the optional
genuine outer observation. Existing `configuration()`, `envelope()`, `initial()`,
`data_digest()` and `runtime_contract(role)` report the effective bound values.
`establish_config(role)` supplies the existing Noise factory with exact H1,
actual outer binding and checked extra-byte geometry. It is a consistency input,
not authentication authority. Only the actual local role of the genuine proof
may consume a bound runtime/setup contract.

The bound profile retains the original requested settings/catalog and effective
values in one owner; the service does not need a second original-profile Arc.
It consumes the original authenticated carrier, Noise/member authority, socket
and original absolute cap; this binding API does not create another I/O or
protocol loop.

The additive optional `OriginalCarrier` status observation exposes the requested
E0/H0/catalog, effective E1/H1/catalog, genuine outer binding and retained outer
lifetime. Its absent value is omitted from existing serialized status. Complete
explicit outer-plan parsing, bounded DER credential reading, strict unsupported
flag refusal and offline inspection are implemented. Their finite parser and
compatibility cases passed in the failed aggregate above; actual new-carrier CLI
startup is still unqualified.

## Preserved failures and actual integration correction

The first actual all-four-family carrier service case
`actual_openvpn_common_service_uses_bound_catalog_for_all_four_families` aborted
after 0.216 s. The preserved
[first](../../work/parallel-features-20261115/parallel-wave5-stack-debug-attempt-1/validation.json)
and [second stack traces](../../work/parallel-features-20261115/parallel-wave5-stack-debug-attempt-2/validation.json)
locate the actual initial Bank/Driver construction, including approximately
244,816 bytes for `new_common_on_carrier` and 192,528 bytes for the carrier
preparation frame. This is a real service integration failure, not a passing
native/device result.

The structural correction moves the same actual Driver into its existing
fallible StateCell through the constructor finish callback before those two
returns. It preserves allocation/error order, original caps and bytes; it adds no
second Driver, I/O loop or task and does not enlarge a test stack. It avoids the
two parent return frames totaling approximately 437,344 bytes. The
[third build attempt](../../work/parallel-features-20261115/parallel-wave5-build-attempt-3/validation.json)
passed, and the [second selected case receipt](../../work/parallel-features-20261115/parallel-wave5-cases-attempt-2/validation.json)
records four directly affected passes: the public initial-only carrier loop,
nonempty original-UDP switching, full-catalog inspection and old APIv4 lifecycle.
That aggregate remains **failed**: the service case then reached an incorrect
test assertion equating the raw outer proof binding with the independently
domain-separated Noise outer binding. A test-only correction checks each exact
domain separately; the actual service case subsequently passed in the final log
above. The
initial compile failure was a private cover `encoded_len` call, subsequently
replaced with the maintained public overhead API before Build2.

The same second case receipt records two actual external full-64 inspection
processes: QUIC-like in 0.069 s and media-like in 0.071 s. Both emitted every
catalog page, retained requested E0/H0, reported effective values as absent and
required a genuine future binding. They made no network, TLS or device startup;
the deliberately missing CA remained unopened and TLS validation was explicitly
false. These positive subprocess results do not change the failed aggregate.
