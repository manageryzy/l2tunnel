# Exact aligned units for timed packing

Status: additive interface implemented with six focused sender tests, including
all 2,588 preserved actual-Python symbols and an exact multi-channel packing,
identity-envelope and receiver-admission round trip. This postdates wave7; a new
aggregate remains pending. The existing aligned
sender writes padded symbols directly into recovery envelopes. Timed packing
needs its exact meaningful units and record boundaries without guessing where
zero padding starts. This slice does not itself allocate recovery source IDs,
schedule native frames or implement the complete packed endpoint.

## Interface and transfer

Add `Sender::pending_unit(&mut self) -> Result<PendingUnit<'_>, Error>`.
The borrowed result exposes `channel`, absolute `record`, exact `bytes`,
`completes_record` and `completes_frame`. Bytes include the original channel and
low16 record serial and all actual body/fragment bytes. Trailing native zero bytes
are retained; only padding generated by the sender is excluded. A context unit
can end its record without ending its native frame. The final fragment of a frame
ends both. Unit IDs and recovery source IDs remain externally owned.

The existing fixed symbol scratch stores the view. Repeated inspection consumes
no context, record, fragment offset or source identity. Existing `write_pending`
and the new view share one internal symbol builder so their meaningful prefix
and zero extension cannot diverge. All existing Python golden outputs remain
unchanged. Invalid configuration/channel and source-envelope errors retain the
existing semantics and bounds.

Add `Sender::commit_unit()` for the distinct local handoff after a bounded packer
has copied the complete exact unit and its metadata. Existing `commit_source()`
keeps its recovery-handoff contract. Both use the same internal fragment/record
advance; neither reports peer receipt or native delivery. Calling either without
copying the complete owned output violates the caller contract. Rust borrowing
prevents committing while a returned unit view remains borrowed.

No extra payload allocation or queue is added. The pending frame and per-channel
encoder contexts retain their existing memory bounds. Work per inspection is
bounded by the configured symbol size; no content scan trims zeroes.

The additive `pending_copies(source_copy::Policy)` classifies that same exact
meaningful unit under the explicit [copy policy](source-copy-policy.md), without
committing a record, fragment or context. Policy validation precedes inspection;
canonical unit parsing and generic-size/context selection do not grant physical
send authority. Existing `pending_unit` and one-copy constructor behavior are
unchanged. This addition is implemented in source with focused acceptance pending.
