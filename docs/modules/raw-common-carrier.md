## Selected raw liveness retry correction

The 2026-11-17 source audit found that an outstanding selected Ping suppressed
all subsequent Ping output. A lost Ping or Pong could therefore exhaust the
unchanged 15-second lower-carrier liveness deadline. The native matrix contains
raw `Expired` failures; this defect is a source-verified contributor candidate,
not proof that it explains every failed native row.

The selected owner now repeats an outstanding logical challenge at the existing
250-millisecond transition retry interval, already committed in the packet
policy. New challenges retain their five-second cadence. Each attempt uses a new
raw sequence extent and the sole
Records owner's fresh protection; it never replays an old ciphertext. A freshly
authenticated repeated Ping recreates the bounded Pong obligation after a lost
reply. Exact packet replays remain rejected, and only a matching authenticated
Pong advances `last_alive`. Neither sending nor receiving a Ping extends the
original liveness deadline. The tuple, control grammar, resource bounds and
existing timer owner are unchanged.

Cancellation before commit consumes neither retry cadence nor sequence space.
Committed WouldBlock output retains its exact bytes and physical receipt token;
it excludes another attempt until that custody is settled. Retry spacing starts
at its actual physical acceptance without changing `last_alive`. Every accepted retry
is accounted as an actual new packet, even when the test link subsequently drops
it. Original expiry still releases the carrier and preserves any completed,
unobserved physical receipt exactly once.
